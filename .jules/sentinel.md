## 2024-05-18 - [Fix Missing Authentication on Sensitive GET Endpoints]
**Vulnerability:** Several GET API endpoints (`/api/telemetry`, `/api/session/state`, `/api/time/current`, `/api/history/list`) were missing the `@_require_api_token` decorator, allowing unauthenticated read access to sensitive telemetry data, session states, and historical records when API tokens were otherwise configured to protect the application.
**Learning:** In Flask Blueprint routing, it's common to remember authentication for state-mutating POST endpoints, but read-only GET endpoints are sometimes overlooked, especially if they are added later or perceived as "just viewing data". The custom `@_require_api_token` decorator must be explicitly applied to all endpoints within a protected namespace (like `/api/*`).
**Prevention:** Audit all endpoints registered with `@app.route` or `@bp.route` to ensure authentication decorators are consistently applied. When adding new endpoints, use a checklist or automated linter to enforce the presence of `@_require_api_token` (or equivalent) unless the route is explicitly designed to be public. Consider moving authentication to a Blueprint-level `before_request` hook if the entire Blueprint requires protection, reducing the chance of human error on individual routes.
