# 物理状态刷新闭环手工测试

> 标准服务端口为 `8890`。本流程显式设置模拟时间，因此固定时间戳是可重复测试数据，不是当前系统时间。
> 任务坐标使用无 DVL 风险的安全基线，确保第一阶段只验证流速超限与遥测过期。

---

为了方便您和同事在前端 HUD 页面上以当前时间（~14:28）完整复现“**物理状态与时间超标拦截 ➔ 后台参数更新 ➔ 发送重新检查通过**”的完整闭环，请对照以下步骤和对话文本进行操作：

---

### 第一阶段：流速超标且数据过期，任务被拦截

#### 1. 【终端准备】设置当前模拟时间、流速超标与数据过期
在终端中执行以下命令，将当前模拟时间设定为 **14:28**，并将观察级 ROV `OBSROV-75-001` 的实时流速设定为不可作业的 **1.5 m/s**（安全上限为 1.2 m/s），数据更新时间设定为 **13:00**（已超出当前时间 1 小时，会触发数据过期警告）：

```bash
# 设定系统模拟时间为 14:28:00
curl -X POST http://localhost:8890/api/time/set \
  -H "Content-Type: application/json" \
  -d '{"time":"2026-07-10T14:28:00+08:00"}'

# 设定观察级 ROV 状态（流速 1.5 m/s，更新时间 13:00）
curl -X POST http://localhost:8890/api/robot/set-state-info \
  -H "Content-Type: application/json" \
  -d '{"robot_name":"OBSROV-75-001","params":{"current_velocity":1.5,"update_timestamp":"2026-07-10T13:00:00+08:00","overall_status":"available","survival_status":"normal","thruster_status":"normal","depth_keeping_status":"normal","sonar_status":"normal","vision_status":"normal","arm_status":"normal","end_effector_status":"normal","acoustic_comms_status":"normal","tether_connection_status":"normal"}}'
```


#### 2. 【前端对话】发送任务描述
进入前端网页，点击 **“重新开始”**（以开启干净的新会话），然后在聊天框中输入并发送以下内容：
> 我想做管缆巡检，开始时间现在，结束时间五小时后，管缆位置在(17.60,111.00)，管缆类型为海底油气管道，起始点(17.60,111.00)，结束点(17.70,111.10)，水深300米，设备型号为观察级深海机器人，具体机器人编号为OBSROV-75-001，携带工具为高清水下摄像机和前视声呐，支持船：海洋石油681

#### 3. 【预期回复】
大模型会返回拒绝与警告信息，明确指出流速超标和环境数据过期：
> ⛔ **当前违规详情：流速状态监测-禁止**
> 当前流速 1.50 m/s，已超过安全上限。强流环境可能导致ROV失控或无法精确定位，任务已禁止执行。建议等待海况改善后重新执行。
> 
> ⚠️ **环境信息已过期**
> 环境信息最后更新于 2026-07-10T13:00:00+08:00，已超出有效时间范围，无法反映实时海况，可能影响作业安全，请更新环境信息后再继续。

---

### 第二阶段：海况转好，更新后台参数

#### 4. 【终端操作】更新流速与数据时间（注入 0.3 m/s，更新时间为 14:25）
模拟海况好转，在终端中执行以下命令，将流速修改为安全的 **0.3 m/s**，更新时间设定为 **14:25**（距离模拟时间 14:28 不足 1 小时，数据处于有效期内）：
```bash
curl -X POST http://localhost:8890/api/robot/set-state-info \
  -H "Content-Type: application/json" \
  -d '{"robot_name":"OBSROV-75-001","params":{"current_velocity":0.3,"update_timestamp":"2026-07-10T14:25:00+08:00","overall_status":"available","survival_status":"normal","thruster_status":"normal","depth_keeping_status":"normal","sonar_status":"normal","vision_status":"normal","arm_status":"normal","end_effector_status":"normal","acoustic_comms_status":"normal","tether_connection_status":"normal"}}'
```

---

### 第三阶段：前端重新检查，解锁任务

#### 5. 【前端对话】发送重新校验请求
在刚才同一个聊天窗口中，不需要重新发送整段任务描述，直接输入并发送：
> 重新检查

#### 6. 【预期回复】
大模型会重新加载校验逻辑，检测到 `OBSROV-75-001` 的流速已降为 `0.3 m/s`，且数据时间已更新，给出绿色的通过结论：
> 收到，已重新校验。
> 
> **【重新校验结果】环境安全 ✅**
> * **流速监测**：0.3 m/s（正常 ✅）
> 
> 此前检测到的流速和数据过期异常已消除，当前参数已满足所有安全约束。
> 请确认是否以上述参数正式下达该任务？（回复“确认”或“是”以生成任务工单）
