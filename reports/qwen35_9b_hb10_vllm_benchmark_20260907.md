# Qwen3.5-9B 推理性能基准测试报告（HB10/GB10 最大稳定显存配置）

> **测试目的**：评测当前 HB10 平台（系统枚举为 NVIDIA GB10）在接近最大稳定统一内存分配下的 Qwen3.5-9B BF16 推理性能，并与 RTX 5090 报告使用相同输入、输出及并发档位进行横向比较。

## 1. 硬件与环境配置（Hardware & Environment）

- **测试设备**：`NVIDIA GB10`，Blackwell，单 GPU，统一内存总量 `121.66 GiB`。
- **最大稳定分配设置**：`gpu_memory_utilization = 0.93`。
- **0.95 探测结果**：启动失败；vLLM 检测到空闲 `113.36 GiB`，而 0.95 需要 `115.57 GiB`。
- **模型权重**：`Qwen3.5-9B`，BF16，路径 `/app/runtime/model/Qwen3.5-9B`。
- **权重实测占用**：`17.66 GiB`；checkpoint 大小 `17.98 GiB`。
- **推理引擎**：`vLLM 0.23.1rc1.dev727+gec0ffaacc.d20260702`。
- **CUDA / 驱动**：容器 CUDA `13.0.2`；宿主驱动 `580.159.03`。
- **最大上下文**：`262,144 tokens`。
- **基准设置**：Prefix Caching 关闭、PagedAttention 启用、`max_num_seqs=64`、`max_num_batched_tokens=32768`、固定生成长度、忽略 EOS。
- **基准 KV Cache**：`87.04 GiB`，可容纳 `2,831,679 tokens`；262K 上下文理论并发 `10.80x`。
- **生产 seagent KV Cache**：Prefix Caching 开启、`max_num_seqs=2` 时为 `90.02 GiB`、`2,911,205 tokens`，262K 理论并发 `11.11x`。

GB10 使用统一内存，`nvidia-smi` 不提供 RTX 5090 风格的独立显存 MB 占用字段，因此以内核启动日志中的 vLLM 内存剖析值为准。

| 短文本交互 | 128 | 128 | 10.2583 | **80.14 ms** | **12.48** |
| 标准对话/任务抽取 | 512 | 256 | 20.5789 | **80.39 ms** | **12.44** |
| 长上下文对话 | 2048 | 512 | 41.5362 | **81.13 ms** | **12.33** |

## 4. 与 RTX 5090 模板结果对比

| 并发 | RTX 5090 输出 tok/s | HB10/GB10 输出 tok/s | 5090 / HB10 倍率 |
| :--: | --: | --: | --: |
| 4 | 318.36 | 52.58 | 6.06x |
| 8 | 623.28 | 100.32 | 6.21x |
| 16 | 1,077.20 | 182.31 | 5.91x |
| 32 | 1,553.80 | 297.01 | 5.23x |
| 64 | 2,286.94 | 377.19 | 6.06x |

标准 512/256 单流下，RTX 5090 报告为 91.42 tok/s，本机为 12.44 tok/s，RTX 5090 约为本机的 7.35 倍。64 并发下，本机达到本轮最高输出吞吐 377.19 tok/s，但从 32 到 64 只提升约 27%，已开始接近计算吞吐饱和区间。

## 5. 关键结论

1. 当前平台无法稳定使用 0.95；在现有系统服务占用下，实测最大可启动档位为 **0.93**。
2. 生产 seagent 的 KV Cache 已由约 76.6 GiB / 225.7 万 token 提升到 **90.02 GiB / 291.1 万 token**，单请求上下文由 32K 放开到模型原生的 **262K**。
3. 单流 BF16 解码约 **12.3–12.5 tok/s**；并发 64 时达到 **377.19 输出 tok/s**。
4. 与所给 RTX 5090 数据相比，本轮 HB10/GB10 多并发吞吐约低 **5.2–6.2 倍**。对比时需注明 vLLM 版本不同（0.23.1 开发版对 0.18.1）、CUDA 版本不同以及 GB10 为统一内存架构。
5. 本测试是纯 vLLM 离线推理。seagent `/api/chat` 还包含意图路由、JSON Schema、业务状态机和串行锁，不应拿它的端到端延迟直接替代纯模型吞吐。
