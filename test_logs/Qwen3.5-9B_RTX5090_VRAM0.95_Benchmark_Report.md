# Qwen3.5-9B 推理性能基准测试报告 (vLLM 0.95 最大显存配置)

> **历史测量说明（2026-09-30 复核）**：数值沿用原实验记录，本轮未重跑硬件测试。按 [benchmark_qwen_performance.py](../scripts/benchmark_qwen_performance.py)，计时范围是整次离线 `llm.generate()`，包含输入处理、Prefill、Decode 和调度开销；脚本字段 `tpot_ms_per_token` 实际为 E2E / 输出 Token 数，`generation_tokens_per_s` 为输出 Token 数 / E2E。脚本未采集首字到达时间或逐 Token 时间，不能报告 TTFT 或纯 Decode TPOT。脚本生成器仍使用旧指标名称，重新生成报告时需按此口径检查。

> **原始数据范围**：现存脚本将三次单流计时取平均后写入 Markdown，未持久化逐次计时或 benchmark JSON/CSV；本轮在仓库及精确相关 `/tmp` 路径未找到独立测量记录。以下数字可进行表内算术核对，不能替代原实验复验。吞吐末位与表中四位小数耗时重算略有差异，均可由显示四舍五入解释，保留原值。部分设备、精度和软件版本文字在生成器中写死，缺少运行时清单时不能据此独立核验实际环境。

> **测试目的**：记录 RTX 5090 (32GB) 在 `gpu_memory_utilization=0.95` 配置下的端到端时延、输出吞吐与并发吞吐，供后续比较整套部署配置；该参数不是已验证的全负载最大安全显存值。

- **测试设备**: `NVIDIA GeForce RTX 5090` (显存总量: `32607.0 MB` / ~32GB)
- **显存占用分配设置**: `gpu_memory_utilization = 0.95`
- **实测显存占用水位**: `29682.0 MB` (91.0% 饱和)
- **模型权重**: `Qwen3.5-9B` (BF16, 物理路径 `/root/autodl-tmp/model/Qwen3.5-9B`)

## 4. 关键结论与 HB10 对比建议 (Conclusions & Comparison Guide)

1. **单卡单流端到端测量**: 在标准交互场景 (512 in / 256 out) 下，输出 Token / E2E 为 **91.42 tokens/s**，E2E / 输出 Token 为 **10.94 ms**；没有单独得到首字或纯解码延迟。
2. **95% 显存分配配置下的已测最高吞吐**: 并发 64 的样本记录输出吞吐 **2286.94 tokens/s**（输入与输出合计 **6860.81 tokens/s**）。这是所测档位的最高值，不能据此认定硬件吞吐极限，也不能将全部显存占用归因于 KV Cache。
3. **与 HB10 对比的关键对照基准**:
   - **吞吐量维度**: 对比相同模型 (Qwen-9B/8B 量级) 在 BS=1, 8, 32, 64 时的生成 Tokens/s。
   - **时延维度**: 当前只能比较相同计时口径的 E2E；若需 TTFT 和纯解码 TPOT，应另行采集首 Token 与后续 Token 的时间。
   - **显存与上下文容量**: 对比最大可容纳并发 KV Cache 块数及最长支持的 Context 长度。
