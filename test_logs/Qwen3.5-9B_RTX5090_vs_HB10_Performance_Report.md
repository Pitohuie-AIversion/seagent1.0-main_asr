## 1. 测试背景与评估维度

本次测试针对大语言模型 `Qwen3.5-9B` (BF16) 在两类典型硬件架构（工作站独立 GPU 与边缘端统一内存系统）上的推理性能进行基准压测与横向对照，旨在为智能体任务规划系统的端侧运控载荷与中心服务部署提供选型依据。

核心量化指标包括：
- **单流交互延迟**：不同输入长度下的端到端响应时间及其按输出 Token 数均摊的耗时。
- **并发吞吐扩展能力**：在 4、8、16、32、64 并发档位下的生成吞吐（Output Tokens/s）及系统吞吐（Total Tokens/s）。
- **内存池与上下文承载上限**：可用 KV Cache 容量及理论支持的最大序列上下文长度。

## 3. 单流推理时延基准 (Batch Size = 1)

测试设置：固定生成长度并忽略 EOS，记录离线整次生成耗时。
注：均摊耗时包含 Prefill、Decode 和其他调用开销，不是纯解码 Token 间隔。短指令样本原记录标注“含冷启”，不能与已预热样本直接作同条件比较。

| 业务场景 | 输入 / 输出 (Tokens) | RTX 5090 E2E (s) | HB10 E2E (s) | RTX 5090 E2E / 输出Token | HB10 E2E / 输出Token | RTX 5090 输出Token / E2E | HB10 输出Token / E2E | 输出吞吐比值 (5090 / HB10) |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **短指令交互** | 128 / 128 | 5.53 (含冷启) | 10.26 | 43.19 ms | 80.14 ms | 23.15 tok/s | 12.48 tok/s | **1.85x** |
| **标准任务抽取** | 512 / 256 | 2.80 | 20.58 | 10.94 ms | 80.39 ms | 91.42 tok/s | 12.44 tok/s | **7.35x** |
| **长上下文任务** | 2048 / 512 | 5.66 | 41.54 | 11.06 ms | 81.13 ms | 90.43 tok/s | 12.33 tok/s | **7.33x** |

### 数据分析
1. **样本输出吞吐**：在标准和长上下文两个样本中，RTX 5090 组合配置的输出 Token / E2E 为 **90.4 ~ 91.4 tokens/s**（均摊耗时约 10.9 ms）；HB10 组合配置为 **12.3 ~ 12.4 tokens/s**（均摊耗时约 80.4 ms）。这不能证明纯解码性能或跨负载稳定性。
2. **端到端交互延迟**：针对常见的 256 tokens 任务抽取输出，RTX 5090 端到端响应时间为 **2.80 秒**，HB10 为 **20.58 秒**。

### 4.3 扩展性与饱和拐点特征
- **RTX 5090**：并发由 4 提升至 64 时，生成吞吐由 318.36 增至 2,286.94 tokens/s（提升 7.18 倍），批次耗时从 3.22 秒增至 7.16 秒；这些采样点没有给出饱和上限。
- **HB10**：并发在 4 至 32 时吞吐由 52.58 增至 297.01 tokens/s；从 32 扩展到 64 时，由 297.01 增至 377.19 tokens/s（按表内数值复算增幅约 27.0%），耗时从 27.58 秒增至 43.44 秒。该组合配置出现收益递减，但没有硬件计数器或受控实验可以区分计算、带宽、调度等原因。

## 5. 原实验配置与解释边界

| 评估维度 | NVIDIA GeForce RTX 5090 | HB10 (NVIDIA GB10) | 测量边界 |
| :--- | :--- | :--- | :--- |
| **输出吞吐** | 单流 ~91 tok/s<br>64并发 ~2,287 tok/s | 单流 ~12.4 tok/s<br>64并发 ~377 tok/s | 为软硬件组合配置的 E2E 输出吞吐，不能单独归因于 SM 或内存带宽。 |
| **显存池规模** | 32 GB GDDR7 (独立显存) | 121.66 GiB LPDDR5X (统一内存) | RTX 5090 物理显存受限；HB10 具备大容量统一内存池。 |
| **KV Cache 空间** | 6.72 GiB (~5.5 万 tokens) | 87.04 GiB (~283.1 万 tokens) | 扣除模型权重后，HB10 的 KV Cache 可用容量是 RTX 5090 的 **13.0 倍**。 |
| **长上下文配置** | 设定 16K<br>未在本文实测 262K 请求 | 配置 262K 上下文<br>原记录理论并发 10.8x | 配置上限和理论容量不是长上下文请求成功率或质量验证。 |
| **功耗与物理形态** | 原记录整卡功耗规格约 575W | 原记录为模块化 SoC | 未测量实际能耗、热稳态、舱内散热或整机集成，不能据此认定部署适用性。 |

## 6. 组合配置比较结论与待验证项

在本文记录的固定负载下，RTX 5090 组合配置的 E2E 更短、输出吞吐更高；HB10 组合配置记录了更大的 KV Cache 和上下文配置容量。两者的版本与配置不一致，因此只能比较这些具体实验组合。

部署选型还需统一模型、推理版本、精度、上下文、预热与负载口径，并补充真实任务质量、TTFT、纯解码 TPOT、并发尾延迟及功耗和散热测量。现有数字不足以证明任一平台满足实时运控闭环、舱内集成或完整上下文可靠运行要求。
