## 1. 测试背景与评估维度

本次测试针对大语言模型 `Qwen3.5-9B` (BF16) 在两类典型硬件架构（工作站独立 GPU 与边缘端统一内存系统）上的推理性能进行基准压测与横向对照，旨在为智能体任务规划系统的端侧运控载荷与中心服务部署提供选型依据。

核心量化指标包括：
- **单流交互延迟**：涵盖不同上下文长度下的端到端响应时间与等效单 Token 解码耗时（TPOT）。
- **并发吞吐扩展能力**：在 4、8、16、32、64 并发档位下的生成吞吐（Output Tokens/s）及系统吞吐（Total Tokens/s）。
- **内存池与上下文承载上限**：可用 KV Cache 容量及理论支持的最大序列上下文长度。

## 3. 单流推理时延基准 (Batch Size = 1)

测试设置：固定生成长度并忽略 EOS，模拟真实交互场景的稳态响应耗时。
注：因采用无流式离线生成，单 Token 延迟包含 Prefill 首字阶段均摊开销。

| 业务场景 | 输入 / 输出 (Tokens) | RTX 5090 耗时 (s) | HB10 耗时 (s) | RTX 5090 单Token耗时 | HB10 单Token耗时 | RTX 5090 解码速率 | HB10 解码速率 | 性能比值 (5090 / HB10) |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **短指令交互** | 128 / 128 | 5.53 (含冷启) | 10.26 | 43.19 ms | 80.14 ms | 23.15 tok/s | 12.48 tok/s | **1.85x** |
| **标准任务抽取** | 512 / 256 | 2.80 | 20.58 | 10.94 ms | 80.39 ms | 91.42 tok/s | 12.44 tok/s | **7.35x** |
| **长上下文任务** | 2048 / 512 | 5.66 | 41.54 | 11.06 ms | 81.13 ms | 90.43 tok/s | 12.33 tok/s | **7.33x** |

### 数据分析
1. **稳态解码速率**：在标准交互长度下，RTX 5090 的解码速度稳定在 **90.4 ~ 91.4 tokens/s**（单 Token 延迟约 10.9 ms）；HB10 稳定在 **12.3 ~ 12.4 tokens/s**（单 Token 延迟约 80.4 ms）。
2. **端到端交互延迟**：针对常见的 256 tokens 任务抽取输出，RTX 5090 端到端响应时间为 **2.80 秒**，HB10 为 **20.58 秒**。

### 4.3 扩展性与饱和拐点特征
- **RTX 5090**：并发由 4 提升至 64 时，生成吞吐由 318.36 线性扩展至 2,286.94 tokens/s（提升 7.18 倍），批处理总延迟从 3.22 秒仅平缓上升至 7.16 秒，未见明显的计算单元饱和现象。
- **HB10**：并发在 4 至 32 之间保持良好线性扩展（52.58 至 297.01 tokens/s）；当并发由 32 扩展到 64 时，生成吞吐仅从 297.01 上升至 377.19 tokens/s（增幅仅 26.9%），总耗时由 27.58 秒激增至 43.44 秒，表明该芯片在 32~64 并发区间已达到其计算单元吞吐上限与内存带宽瓶颈。

## 5. 架构与性能瓶颈对比分析

| 评估维度 | NVIDIA GeForce RTX 5090 | HB10 (NVIDIA GB10) | 架构归因 |
| :--- | :--- | :--- | :--- |
| **算力与流速** | 单流 ~91 tok/s<br>64并发 ~2,287 tok/s | 单流 ~12.4 tok/s<br>64并发 ~377 tok/s | RTX 5090 具备更大规模 SM 计算阵列及满血 GDDR7 高带宽；HB10 受限于边缘低功耗设计，计算核规格较小。 |
| **显存池规模** | 32 GB GDDR7 (独立显存) | 121.66 GiB LPDDR5X (统一内存) | RTX 5090 物理显存受限；HB10 具备大容量统一内存池。 |
| **KV Cache 空间** | 6.72 GiB (~5.5 万 tokens) | 87.04 GiB (~283.1 万 tokens) | 扣除模型权重后，HB10 的 KV Cache 可用容量是 RTX 5090 的 **13.0 倍**。 |
| **长上下文支持** | 设定 16K<br>(单卡无法支持 262K) | 支持 262K 原生极限上下文<br>(理论并发 10.8x) | RTX 5090 显存不足以承载单请求 262K 上下文所需的 KV Cache（极易 OOM）；HB10 具备原生支撑能力。 |
| **功耗与物理形态** | 整卡功耗约 575W，需独立机箱与大功率电源 | 模块化嵌入式 SoC，功耗与体积明显更低 | 独显适合数据中心/母船工作站；SoC 适合舱内机器人本体集成。 |

---

## 6. 工程选型与部署结论

1. **中心控制站 / 实时人机交互节点**：
   - **推荐方案**：NVIDIA GeForce RTX 5090。
   - **技术依据**：单流解码耗时低于 11 ms，256 tokens 任务抽取响应时间控制在 3 秒以内，64 并发下吞吐超过 2200 tokens/s，能够满足多操作员、多客户端高频语音与自然语言交互的低延迟要求。
2. **水下机器人 (ROV) / 边缘自主运控载荷**：
   - **推荐方案**：HB10。
   - **技术依据**：受限于水下密封舱容积、散热条件及供电功率，HB10 具备边缘集成可行性。其 87 GiB 以上的超大 KV Cache 支持加载 262K 原生全长上下文，允许机器人本体在离线状态下驻留超长操作规程、历史状态链及领域知识库。虽单流流速相对受限（12.4 tokens/s），但对于秒级到十秒级的非高频离线规划任务已满足闭环需求。
