# 任务归档与执行下发

任务确认成功表示 TaskIntent 已生成并归档。机器人是否接收、是否执行，以 `ros2_dispatch` 和机器人遥测分别表示。确认回复不提前承诺已经下发。

`src/dispatch/task_dispatch.py` 是 Web 自动下发、`POST /api/mcp/dispatch` 和 `dispatch_dialogue_result()` 的统一执行入口。入口使用原已归档 intent，不重新生成任务编号。

| state | 含义 | 显式操作 |
| --- | --- | --- |
| SENT | 指令已写入 ROS 传输，或已有机器人接收证据；不等于执行完成 | 查看遥测 |
| FAILED | 校验过程异常、桥接离线或可确定任务尚未发送的错误 | 重新检查并下发 |
| UNKNOWN | 发送可能发生但结果未确认，或旧历史缺少发送证据 | 核对发送记录；没有接收证据时不重发 |
| SCHEDULED | 尚未到计划开始时间，任务已保存 | 到期后手动检查执行条件并下发 |
| BLOCKED | 执行前校验未通过 | 根据原因刷新条件或创建新任务 |

返回对象还包含 `message`、`retry_allowed`，可选 `error`、`task_id`、`task_id_hex`、`scheduled_for`。前端仅在 `retry_allowed=true` 时提供显式操作，后端每次重新决定是否允许发送。

未来任务当前没有后台自动调度。到期后使用 `POST /api/mcp/dispatch`，请求体为 `{"session_id":"..."}`。服务会执行 `purpose="runtime_execution"` 的最新设备/环境校验；已经超过结束时间的任务不允许下发。任务未到期时，重复检查仍返回 SCHEDULED。

该接口默认禁止自定义 TaskIntent。即使启用 `ALLOW_MCP_CUSTOM_INTENT`，也必须提供已确认会话，且 payload 与会话的归档结果完全一致，以保留可核验的设备选择和执行上下文。

发送结果同时保存在 Manager 和会话历史中。恢复历史不会触发发送。旧历史没有发送结果时显示 UNKNOWN；只有持久下发记录或机器人接收记录能解除该不确定状态。

在 bridge 中，SENDING 是不确定结果，不是成功。发送中断或发送成功后的记录落盘失败都保留这一证据。仅凭“没看到遥测”不能断言发送失败；同任务 ID/类型的正向接收证据可以把记录核对为 SENT。

任务正式文件链接成功后的 fsync 失败会保留原正式编号和 `_pending_published_intent`，确认态暂停修改。再次“确认发布”只核对同一份文件并重做持久化确认，不重占编号、不覆盖文件。待核对记录也写入历史，恢复历史后可继续。进程在正式文件出现与待核对历史记录保存之间直接终止时，仍可能需要人工核对正式文件。

现有经纬度直接映射到 odom x/y 的兼容规则保持不变。该规则与接收端的实际坐标约定、原点必须单独联调确认；本轮没有擅自切换地理投影或默认原点，也没有通过实机验证该契约。
