# ADR-007：DialogueManager 快照恢复的内存原子性

## 状态

已确认，2026-08-13。

## 背景与问题

`DialogueManager.load_snapshot()` 同时恢复会话标识、对话历史、任务阶段、任务模式、对话模式、控制状态、`SlotStore`、派生缓存以及已发布任务结果。

旧实现存在两个相互关联的问题：

1. 仅在 `session_state_v2` 开启时严格校验 `phase` 和任务 `mode`；默认关闭特性开关时，非法值可以进入运行时状态。
2. 恢复过程直接逐项修改当前管理器。例如先写入 `session_id`，随后才校验 `conversation_history`。后续任一校验失败时，当前会话可能停留在半恢复状态。

这会破坏“失败关闭”约束：失败的历史恢复请求不应改变服务中原本有效的会话。

## 已确认范围

本轮只处理快照恢复的状态校验和内存原子性，并补充对应测试。不修改 ASR、坐标解析、TaskIntent 校验、API 契约或前端行为。

必须保持：

- 兼容旧版扁平快照和 `snapshot_version=2` 快照；
- `dialogue_mode="uncertain"` 继续映射为 `knowledge_qa`；
- `done` 阶段继续核验 final 文件，核验失败时回退到 `collecting`；
- `SlotStore` 恢复、Intent ID 补建以及 shadow comparison 的既有语义；
- `session_state_v2` 开启时继续执行 SessionState 契约校验。

## 决策

采用“隔离候选管理器 + 单次提交”方案：

1. `load_snapshot()` 创建一个与当前管理器共享只读依赖、但拥有独立运行时状态的候选 `DialogueManager`。
2. 所有输入结构、枚举值、状态组合、`SlotStore`、标识符、final 文件和 SessionState 契约均在候选对象上完成恢复与校验。
3. `phase` 必须属于 `VALID_PHASES`，任务 `mode` 必须属于 `normal` 或 `emergency`；此规则不依赖特性开关。
4. 只有候选恢复完整成功后，才将全部快照相关运行时字段一次性替换到当前管理器。
5. shadow comparison 在提交成功后运行；候选失败时不记录成功恢复后的状态，也不改变当前管理器。

这里的“原子”指当前 `DialogueManager` 的可观察内存状态：恢复要么完整生效，要么完全不生效。文件系统中的每日 Intent ID 计数仍保持现有的单调、不复用语义；极端晚期故障可能造成编号跳号，但不会造成编号重复或当前会话半恢复。

## 备选方案

### 原地修改后异常回滚

需要完整复制所有可变状态，并确保新增字段同步加入回滚列表。`SlotStore` 内含锁和复杂状态，深拷贝容易失效；若回滚本身抛错，还会掩盖原始异常。因此不采用。

### 仅调整赋值顺序

可以修复 `session_id` 的已知提前赋值，但未来新增的晚期校验仍可能再次引入部分修改，无法建立结构性保证。因此不采用。

## 测试与验收

新增测试必须先在旧实现上失败，并验证默认 `session_state_v2=false` 时：

- 非法 `phase` 被拒绝且管理器状态完全不变；
- 非法任务 `mode` 被拒绝且管理器状态完全不变；
- 在读取新 `session_id` 后出现其他字段校验失败时，原 `session_id` 及其余运行时状态完全不变。

随后运行现有 SessionState 恢复测试、相关历史/API 测试和完整离线测试集。验收要求是定向测试通过，且无新增回归；若完整测试集存在既有失败，必须单独报告而不能宣称全量通过。
