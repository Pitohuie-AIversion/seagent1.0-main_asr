# ADR-005：模型负责语义判断，代码负责安全执行

## 状态

Accepted（第二阶段实施中，2026-08-13 用户确认）

## 背景

现有正常对话路径在模型判断前后叠加了关键词快速通道、WRITE 证据门、
CLARIFY 二次改写和 DialogueManager sticky 覆写。同一条输入会被多次重新分类，
造成固定话术可写、自然表达不可写，以及 QUERY 被误送入抽取器。

## 决策

自然语言的 `READ`、`WRITE` 和 `CLARIFY` 以模型输出的 `InteractionPlan` 为唯一
语义结论。后端不再根据业务关键词改变这些操作类型。

确定性代码只负责：

1. InteractionPlan schema、类型、枚举和置信度校验；
2. 模型给出的控制动作枚举及当前状态权限校验；
3. QUERY 只读不变量；
4. Slot 候选白名单、类型、单位和合法值校验；
5. 状态机合法转移、硬约束、确认和发布权限；
6. SlotStore 事务及任务文件原子发布和恢复。

LLM 路由失败或协议非法时统一澄清，不再通过业务关键词猜测写入。模型返回
WRITE 后仍必须经过 Extractor、Validator 和 SlotStore；路由结果不代表写入成功。

## 第一阶段范围

- 正常路径绕过确定性语义快速通道；
- 移除 WRITE 的关键词证据否决；
- QUERY 严格只读，不进行 sticky 覆写或异步写入；
- 删除控制词二次语义解析，保留控制动作枚举、状态权限、硬约束和发布事务；
- 回复继续以 `accepted_updates` 为唯一已提交事实。

## 第二阶段决策

用户进一步确认：除写状态授权、硬约束、明确发布、事务一致性和候选域外值拒绝等
底线外，自然语言理解与模糊候选消歧均应优先使用模型语义，而不是继续叠加关键词
和精确字符串门。

因此：

1. `operation` 是路由计划唯一不可缺少的语义字段；`dialogue_mode`、
   `needs_clarification` 由代码从 operation 推导。
2. `subject_type`、`relation`、`source_policy`、`query_intent` 等只读检索元数据采用
   best-effort 校验；异常值退化为安全默认值，不得让一个合法 READ 整轮失败。
3. 低置信度 READ 仍进入无副作用回答；低置信度 WRITE/CONTROL 继续澄清，避免
   不确定语义产生状态副作用。
4. 枚举输入依次经过标准值、明确 alias、模型语义消歧；模型只能从本轮权威
   `allowed_values` 中返回标准值，但不要求用户逐字复述标准名称。
5. 多候选推荐可以由模型结合候选证据选择；无法验证模型选择时只展示候选并询问
   偏好，不得以列表第一项冒充智能推荐。
6. 确定性复合请求守卫只阻止同轮创建多个已识别任务；域外分句和混合问答交给模型
   与抽取器处理，不再靠动作词猜测。
7. 普通只读对话使用通用推理角色；通用领域问题不注入全量项目配置。任务进入终态
   后已发布 artifact 保持不可覆盖，但会话仍允许 READ/CLARIFY；新的 WRITE 沿现有
   安全事务创建新草稿和新 intent_id。

## 编号选择的可见来源边界

“第三个”“选 2”“最后一个”等表达仍由模型结合上下文解析为标准候选，但序号本身
只构成选择意图，不构成候选顺序的来源。执行器必须在写入前确认：

1. 紧邻上一条 assistant 消息明确展示了编号候选；
2. 对应编号行唯一指向模型选择的标准值或无歧义 alias；
3. 该标准值仍属于目标字段当前 `allowed_values`；
4. 中间出现新的 assistant 回复后，旧编号列表不再授权后续写入。

任一条件不成立时保留模型的语义判断证据，但删除写入候选并进入澄清。不得使用
仅存在于 required schema、`expected_slot_options` 或其他后台结构中的隐藏顺序。
直接说出候选名称、自然语言模糊描述和紧邻助手给出的单一明确推荐不受编号门禁
影响，继续沿各自的白名单与来源校验路径处理。

决策记录：采用“模型解析 + 提交前可见来源校验”，拒绝“完全信任后台候选顺序”
（会产生用户未见候选的误写）和“代码直接替代模型解析所有指代表达”（会重新制造
固定话术依赖）。实现不引入新依赖，校验成本仅与当前字段候选数量和上一条回复长度
线性相关。

## 第二阶段非目标

- 模型不得直接写 SlotStore 或跳过 Validator；
- 不放宽硬约束、明确发布和原子持久化；
- 不允许模型生成 `allowed_values` 之外的最终枚举值；
- 本轮不重写机器人 registry、任务 schema 或约束阈值。

## 非功能假设

- 每轮允许一次路由模型调用，语义正确性优先于节省该次调用；
- 模型不可用时宁可澄清，也不猜测写入；
- 并发、幂等、原子性和 fail-closed 要求保持不变；
- 不引入新依赖；
- 离线 Mock 不伪装自然语言理解能力，未显式注入计划时统一澄清；
- 本阶段暂不解决跨进程会话恢复。

## 备选方案

1. 继续扩充关键词：维护成本和误判持续增长，拒绝。
2. 模型直接写 SlotStore：会绕过安全和事务边界，拒绝。
3. 模型语义计划 + 确定性执行内核：采用。

## 验收

- 模型 WRITE 不因措辞缺少关键词而降级；
- 模型 READ 在任务草稿和缺失槽位上下文中仍保持 QUERY；
- QUERY 不调用 Extractor、不修改 SlotStore；
- 低置信度 WRITE/CONTROL 或缺失 operation 的非法协议降级 CLARIFY；
- 模型失败不触发猜测式业务写入；
- 紧急控制和发布安全边界保持原行为。
- READ 的非关键元数据错误不会阻断回答，且始终保持状态不变；
- 模糊枚举表达可经模型映射到当前合法候选，域外结果仍被拒绝；
- 多候选无法可靠推荐时不再默认选择列表第一项；
- 可见编号候选可以跨轮选择；隐藏、过期、重复编号或与选择值不一致的列表不得写入；
- 已发布 artifact 不被覆盖；后续修改创建新草稿，同时用户可继续只读对话。
