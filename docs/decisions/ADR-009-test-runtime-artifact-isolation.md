# ADR-009：测试与用户运行产物统一隔离

- 状态：已接受
- 日期：2026-08-14

## 背景

任务编号生成器会同时读取持久化计数文件和 task/history 目录中的既有产物。
过去部分测试只替换计数文件路径，仍可能扫描或写入
`/root/autodl-tmp/result`，导致测试结果依赖用户运行序号，并消耗正式编号。

## 决策

所有自动化测试在导入业务模块之前统一设置一次性测试根目录，并从该目录派生：

- `SEAGENT_RESULT_DIR`；
- task 目录；
- history 目录；
- 编号计数文件、锁文件及其他结果缓存。

pytest 通过仓库根级 `conftest.py` 启动隔离；包方式运行 unittest 时通过
`tests/__init__.py` 使用同一引导。子进程继承相同环境变量，不创建另一套用户可见目录。
如需保留测试产物，可显式设置 `SEAGENT_TEST_RESULT_DIR`；否则测试结束时删除一次性目录。

测试引导会清除调用环境继承的 `SEAGENT_TASK_DIR` 和 `SEAGENT_HISTORY_DIR`，使二者
从当前 `SEAGENT_RESULT_DIR` 派生。单个测试临时覆盖 result 根时，其 task/history
也随之切换，不会被全局测试目录反向覆盖。

用户运行仍使用生产默认目录或用户显式提供的运行目录。测试不得重置、迁移、删除或
根据生产计数文件构造断言。

## 备选方案

1. 每个测试单独 patch 路径：容易遗漏，已出现真实污染，不采用。
2. 固定仓库内测试目录：跨运行累积状态，并发任务易互相影响，不采用。
3. 在生产代码中根据 pytest/unittest 进程名猜测环境：混合测试逻辑与生产逻辑，不采用。

## 验收

- 测试进程解析出的 result/task/history 均位于测试根目录；
- 子进程继承同一测试根目录；
- 真实编号预约只在测试根目录产生计数和锁文件；
- 完整测试前后用户 `.id_sequences.json` 内容不变；
- 用户服务默认结果路径语义保持不变。
