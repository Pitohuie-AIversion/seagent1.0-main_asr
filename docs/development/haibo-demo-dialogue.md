# 海博会对话演示脚本与核对要点

如需演示“5 小时后开始，并完成正式提交”，使用[已实测的 7 轮提交脚本](haibo-demo-five-hour-submission.md)。下文保留原“1 小时后开始”的草稿校验演示。

本脚本已使用实际网页与 Qwen3.5-9B 交互验证。验证实例为 `http://127.0.0.1:8891`，使用独立任务数据，未连接 ROS。原 `8890` 进程未重启，以保留其中的会话；它尚未加载本轮后端修复。

## 演示终点

这段演示展示“自然语言输入 → 参数收集 → 约束校验”。最终所有必填参数收集完成，但任务停在软警告处理阶段，尚未发布。当前遥测最后更新于 2026-08-27，系统无法据此确认当前设备健康和海况。

不要把“参数收集完成”讲解为“任务已发布”或“机器人已经执行”。按当前配置，近时任务即使确认接受软警告，发布前仍须通过设备状态时效检查；过期遥测不会因确认软警告变成有效数据。

## 逐轮输入

使用新会话，每轮等待系统回复后再发送下一句。模型的具体措辞可以不同，以已保存字段和右侧看板为准。

| 轮次 | 演示者输入 | 核对结果 |
| --- | --- | --- |
| 1 | 我要创建一个任务。 | 等待指定任务类型，不自动猜任务 |
| 2 | 任务类型是管缆巡检。 | 类型为管缆巡检 |
| 3 | 管缆类型是电力电缆。 | 管缆类型正确 |
| 4 | 1小时后开始。 | 开始时间为本轮系统时间加 1 小时；结束时间仍待补充 |
| 5 | 持续3小时。 | 结束时间等于已保存开始时间加 3 小时 |
| 6 | 起点是北纬19.9度、东经113.6度。 | 起点经纬度正确，时间不改变 |
| 7 | 水深300米。 | 水深为 300 米 |
| 8 | 使用AUV-324cc-001。 | 机器人编号、系列、型号正确关联 |
| 9 | 携带侧扫声呐。 | 携带工具为侧扫声呐 |
| 10 | 结束点是北纬20.0度、东经113.7度。 | 终点经纬度正确 |
| 11 | 支持船使用海洋石油681。 | 必填字段齐全；显示待处理软警告与遥测过期提示 |

此时可以讲解：“系统已把对话转为结构化任务，并识别出状态数据过期，因此这里需要处理校验提示，尚未发布任务。”

## 补充演示

另开新会话，先输入“我要创建管缆巡检任务。”，再输入：

> 任务1小时后开始持续4小时 电力

预期一次记录开始时间、结束时间与电力电缆，继续询问坐标和水深。时间以系统模拟时钟为基准，不以演示者电脑的时区或钟表为基准。

也可分两轮输入“1小时后。”和“持续4小时。”。第一轮只记录开始时间；第二轮才计算结束时间。

在完整草稿中输入“先不修改任务，请问当前机器人的设备状态正常吗？”，应说明遥测过期、无法确认当前状态，并保持任务参数不变。

## 本轮发现与修复

| 发现 | 修复后的行为 |
| --- | --- |
| 回复中的具体时间与保存值不一致；把未来开始时间称为当前时间 | 回复核对已提交时间，剔除错误解释 |
| “1小时后。”可能被误当作时长，额外生成结束时间 | 相对开始时间与持续时长分别取证，没有时长或明确结束时间就不新增结束时间 |
| 缺失字段标题数量、编号、内容重复或不一致 | 按真实缺失字段修正异常列表，保留正常示例与选项 |
| 软警告处理指引重复，或误称已经进入发布确认 | 依据实际阶段呈现指引，去掉重复操作段和无依据的后续自动核验承诺 |
| 历史遥测显示为当前正常/可用 | 聊天区与看板明确显示过期或未知，历史数值不冒充实时指标 |

最初 11 轮记录的开始时间加 1 小时、结束时间再加 3 小时的计算本身正确，主要错误发生在回复复述中；补充验证另发现并修复了裸相对时间误生成结束时间的问题。

## 仍可改善的措辞

实测首轮泛化输入“我要创建一个任务。”可能暴露 `task_type` 等内部字段名；部分日期示例可能早于当前模拟时间，模型也可能用“任务已创建”指代草稿建立。最终第 11 轮还有“目前收集”这样的清洗残句，补充状态问答中的“接受软警告继续执行”也未明确区分继续工作流与实际执行。支持船“可用”来自静态船只目录的 `available: true`，不是本轮取得的实时船舶状态。这些没有改变保存状态，但展示表达仍可打磨。现场以工作单阶段和已保存值为准，不能凭模型的一句“已创建”判断任务发布成功。
