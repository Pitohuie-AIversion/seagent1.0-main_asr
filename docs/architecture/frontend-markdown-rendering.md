# 前端 Markdown 安全渲染设计

## 理解摘要

- 大模型回复以纯文本经 `/api/chat` 返回，Markdown 标记暴露发生在前端消息渲染层。
- 现有 `renderMarkdown()` 只处理粗体和斜体，不能正确渲染标题、列表、引用、代码块和表格。
- 普通问答、任务回复、欢迎消息、翻译消息与历史消息需要使用统一的展示规则。
- 后端接口、DialogueManager、ASR、任务状态机与历史持久化格式保持不变。
- 助手消息支持完整、安全的 Markdown；用户消息继续按纯文本展示。
- 页面必须离线可用，不依赖公共 CDN；渲染失败时安全降级为纯文本。
- 图片和原始 HTML 不属于本轮支持范围。

## 假设与非功能要求

- 模型回复规模以当前对话输出为准，浏览器同步解析不会造成可感知阻塞。
- 原始消息仍是唯一持久化内容，不持久化渲染后的 HTML。
- 第三方脚本固定版本并随项目发布，记录来源和许可证，便于维护与安全更新。
- 所有潜在不可信内容在写入 `innerHTML` 前必须经过 HTML 净化。
- 依赖加载或解析失败不得阻断普通对话、ASR 或任务流程。

## 方案比较

1. **Marked + DOMPurify，本地打包（采用）**：Marked 解析 GFM，DOMPurify 对 HTML 做严格白名单净化。职责清晰，覆盖所需语法。
2. **markdown-it + DOMPurify**：可配置能力更强，但本轮没有相应扩展需求；现有 `markdown-it-py` 也不能直接用于浏览器。
3. **后端渲染 Markdown**：会让 API 与历史数据承载展示层 HTML，并需要额外后端净化，扩大接口和持久化影响面。

## 最终设计

数据流为：助手消息原文 → Marked 解析 → DOMPurify 严格净化 → 聊天气泡。用户消息走独立的纯文本转义分支。

新增独立的前端渲染适配器，统一处理欢迎消息、普通回复、任务回复、翻译结果和历史恢复。适配器允许标题、段落、粗体、斜体、删除线、列表、引用、链接、代码块、表格和水平线；禁止脚本、样式、iframe、SVG、图片、事件属性和任意数据属性。链接仅允许明确的安全协议或相对地址。

第三方依赖从本地静态目录按“解析器 → 净化器 → 适配器 → 业务脚本”的顺序加载。任一依赖不可用或解析抛错时，适配器返回 HTML 转义后的纯文本，并保留换行可读性。

## 测试策略

- 静态契约：本地资源存在、加载顺序正确、业务脚本只使用统一渲染入口。
- Markdown 行为：标题、列表、引用、链接、代码块、表格及中文换行正确渲染。
- 安全行为：脚本、事件属性、危险协议、iframe、SVG、图片和畸形 HTML 无法执行或进入最终 DOM。
- 角色行为：助手消息解析 Markdown，用户消息保留 Markdown 字面文本。
- 故障行为：Marked 或 DOMPurify 缺失时安全降级且无未捕获异常。
- 回归行为：欢迎消息、翻译、历史恢复、普通对话、ASR 和任务流程保持可用。

## 决策日志

| 决策 | 备选方案 | 原因 |
| --- | --- | --- |
| 在前端渲染 Markdown | 后端渲染 | 保持 API 与持久化为纯文本，隔离展示职责 |
| 使用 Marked + DOMPurify | 自写正则、markdown-it、后端解析 | 完整 GFM 支持与独立安全净化边界 |
| 本地固定依赖 | 公共 CDN | 满足离线运行与可重复部署 |
| 用户消息只显示纯文本 | 所有角色均解析 Markdown | 避免输入被误解为富文本并收紧攻击面 |
| 禁用图片和原始 HTML | 完整放开 HTML | 避免追踪、布局破坏和额外安全风险 |
| 依赖异常时降级 | 阻止消息展示 | 保证核心对话流程可用 |

## 验收标准

- 常见 Markdown 标记不再裸露且样式清晰。
- 不可信内容不能执行脚本或注入危险元素、属性和链接。
- 所有助手消息入口使用同一渲染器，用户输入保持纯文本。
- `/api/chat`、历史文件和任务状态机契约无变化。
- 定向测试和完整回归测试无新增失败。
